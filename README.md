# 冷链记录仪校时平台

单台冷链温度记录仪的校时网页：记录仪断电重启后时钟失准，数据员上传原始 CSV
（开机段号、本地秒数、温度），再为每个开机段录入两枚「本地秒数 ↔ UTC」校时锚点，
系统对两锚点之间的读数做线性校时，质检组即可按 UTC 日期读取可信的温度原始点。

质检员还可上传**独立校准仪的 UTC/温度 CSV**（参考点），系统在参考仪覆盖时段内
将记录仪的已发布校时读数与参考点做唯一配对，核对记录仪测值是否偏温。

技术栈：FastAPI + SQLite（WAL），服务端渲染页面 + JSON API，后台线程异步重算。

## 快速启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据持久化在命名卷 `coldchain-data`（容器内 `/data/app.db`）。

本地开发（无需 Docker）：

```bash
pip install -r requirements-dev.txt
uvicorn app.main:app --reload        # http://localhost:8000
pytest -q                            # 运行自测
```

## 使用流程

1. **上传数据**（`/upload`）：CSV 三列 `segment,local_seconds,temperature`
   （支持中文表头 `开机段号,本地秒数,温度`，也支持无表头按此顺序）。
   - 累计最多 **2000** 点，超限整批拒绝；
   - 同一开机段内本地秒数不能重复（文件内或与已有数据），冲突整批拒绝；
   - 每批分配批次号，行号为 CSV 数据行序号（从 1 起）。
2. **校时锚点**（`/anchors`）：每段录入两枚锚点（本地秒数 1 < 本地秒数 2，
   且 UTC 必须递增）。两锚点之间的读数按线性插值校时；范围外或无锚点的读数
   **留存待校时**。**更正锚点必须提交所见版本**（乐观并发，版本不符返回 409）。
3. **按日查询**（`/query`）：按 UTC 日期查看已校时读数，每行显示
   **批次号、原行号、锚点版本**、校时版本；页面下方列出待校时读数及原因。
4. **参考数据**（`/reference`）：上传参考仪 CSV 两列 `utc,temperature`
   （中文表头 `时间,温度`，或无表头按此顺序），并输入**允许对时偏差（秒）**与
   **温差限值（℃）**。单文件最多 **2000** 条，**每次上传整体替换旧参考集**；
   同一时刻允许出现多次（留给配对环节判冲突，而非入库时拒绝）。
5. **温度核对**（`/verify`）：按当前参数执行核对并展示结果（见下节）；
   页面上可调整偏差/限值并保存重算。
6. **处理状态**（`/`）：点数、重算状态、校时版本、数据代次、锚点/批次/
   参考集概况，可手动触发重算。

## 温度核对规则

- **核对范围**：参考仪覆盖时段 `[最早参考点, 最晚参考点]` 内的**已发布校时读数**。
  候选配对面向全体已发布读数（不被时段截断，保证边缘参考点可配对）；
  但**时段外的读数不计缺失**、不影响合格判定。
- **配对**：候选边为 `|参考点UTC − 校时读数UTC| ≤ 允许对时偏差`（闭区间）。
  只有**双方各自只有一个候选**的 1-1 连通分量才配对，**读数不复用**；
  任一侧多候选的整簇列为**冲突**；没有任何候选的点列为**缺失**
  （区分「参考点无对应记录仪读数」与「时段内记录仪读数无对应参考点」）。
- **判定**：配对温差 = 记录仪温度 − 参考仪温度，`|温差| ≤ 温差限值` 为合格
  （闭区间）。**冲突或缺失不得判为温度合格**；只有**全部唯一配对且无超限**
  才显示「一致（温度核对合格）」。
- **结果明细**：配对温差表、超限项、冲突簇、两侧缺失清单；每行列出
  **两侧原行号**，记录仪侧保留**批次号、锚点版本**、校时版本。

## 核对的版本一致性

- 每次核验基于**同一完整发布版**（一致快照读取，前后复核
  `(校时版本, 数据代次, 已校代次)`）。
- 上传记录仪数据或更正锚点后，**重算未追平期间结果只能标为「旧版回看」**；
  核验期间发生换版则自动重试，重试仍不稳定同样标为「旧版回看」——
  旧版回看下**绝不显示当前合格**（`qualified` 恒为 false）。
- 参考集替换与核对参数保存不影响校时，不触发重算。

## 一致性设计（校时）

- **原子换版**：每次重算结果在单个事务内整体替换。读数跨日时，
  「旧日移除 + 新日加入」同事务生效；计算或提交失败时旧版本原样保留，
  **绝不提供半版**。
- **迟到计算不回退**：上传/锚点变更递增 `state_generation`；重算按一致快照
  计算，提交前复核代次，已过期则丢弃重算。校时版本号单调递增。
- **重算期间可写可读**：重算在后台线程进行，期间可继续上传新点，
  查询始终看到完整的旧版本；新点在随后的换版中生效。
- **重启恢复**：代次持久化于 SQLite，服务重启后自动比对并补算——
  所有已接纳且处于锚点范围内的点最终都会进入当前版。

## JSON API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/uploads` | 上传记录仪 CSV（multipart `file`），返回 `{batch_id, accepted}` |
| POST | `/api/anchors` | 录入/更正锚点 `{segment, local1, utc1, local2, utc2, version?}` |
| GET | `/api/readings?date=YYYY-MM-DD` | 按 UTC 日查询已校时读数 |
| GET | `/api/pending` | 待校时读数及原因 |
| GET | `/api/status` | 点数、重算状态、代次、锚点、批次、参考集概况 |
| POST | `/api/recalc` | 手动触发重算 |
| POST | `/api/reference` | 上传参考仪 CSV（multipart `file` + 表单 `deviation_s,temp_limit`），整体替换参考集 |
| GET | `/api/reference` | 参考集概况：点数、覆盖时段、核对参数、最近批次 |
| GET | `/api/verify` | 执行温度核对；可用 `?deviation_s=&temp_limit=` 临时覆盖参数（不落库） |

错误返回 `{detail, code, errors?, current_version?}`；锚点版本冲突为 409。

`/api/verify` 返回要点：`verdict`（`consistent` / `not_consistent` /
`no_reference`）、`currency`（`current` / `stale`）、`qualified`
（仅当前版且全部唯一配对无超限才为 true）、`stale_reasons`、`counts`、
`pairs`（含两侧行号、批次号、锚点版本、温差、对时差）、`over_limit`、
`conflicts`、`missing`。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_PATH` | `data/app.db`（容器内 `/data/app.db`） | SQLite 路径 |
| `MAX_POINTS` | `2000` | 累计点数上限 |
| `MAX_REF_POINTS` | `2000` | 参考点集点数上限（每次上传整体替换） |
| `REF_DEVIATION_S` | `30` | 默认允许对时偏差（秒），上传/核对时可覆盖 |
| `REF_TEMP_LIMIT` | `0.5` | 默认温差限值（℃），上传/核对时可覆盖 |
| `WORKER_ENABLED` | `1` | `0` 时关闭后台线程，变更后同步重算（测试用） |
| `RECALC_DELAY` | `0` | 重算提交前人为延迟秒数（演示/测试并发窗口） |

## 已知边界

- 面向单台记录仪、≤2000 点的场景，全量重算代价可忽略，未做增量计算。
- 校时结果毫秒精度；锚点区间按闭区间处理。
- 参考集为「当前一套」，上传即整体替换；历史参考批次仅留上传记录。
- 核对结果按需实时计算、不落库；每次打开 `/verify` 都基于当前发布版重算。
- 单参考点时覆盖时段退化为一个瞬间：配对照常（候选不被时段截断），
  但「时段内读数缺失」判定几乎没有意义，建议参考点覆盖完整时段。
- 未实现鉴权与多用户，部署在内网/受信环境。
